    An AI assistant in the playground (MCP) fork

    An AI assistant on your computer (Claude Code, Claude Desktop, Codex, Gemini CLI or another MCP client) works on the site in your playground tab: it reads and writes the site's files, runs PHP and Joomla's console, makes requests to the site, and shows you a page. Ask it, for example, to install an extension and add some content, or to build a small module and show it.

    It works through a small MCP server on your computer, which talks to the playground tab. So there is no demo link: you add the server to your assistant once, the assistant gives you the link to open, and the page asks you before it connects. The site stays in your browser, as always.

    How to set it up How it works

    Test a pull request of Joomla

    The site opens without the patch. Apply patch in the toolbar applies it and shows the same page again, now with the changes; Revert patch takes them out, so before and after are one click apart. The playground starts the nightly build of the pull request's branch (such as 6.2-dev): the branch as it is now, not its last release. It says when it does not have that branch.

    As a link: …/joomla-playground/?pr=48831, with &url= for the page, e.g. ?pr=48831&url=/administrator/index.php?option=com_config. Changes to JavaScript or CSS (in build/media_source) are not built, so only PHP, template, language and XML changes show. See the open pull requests.

    A GitHub token

    Without a token, GitHub allows the Patch Tester 60 requests an hour; one Fetch Data uses about four. Click GitHub token… in the playground's toolbar and enter one: this browser remembers it and gives it to the Patch Tester of every new playground, so you enter it once. Use a token without permissions, because the pages of this site can read it, including the pull requests you test: a fine-grained token with access to public repositories only (read-only). Never put a token in a blueprint or a link: anyone with the link can read it.

    Guided tours of the Joomla User Guide

    Tutorials of the Joomla User Guide as guided tours: each link opens a playground in the language of the tour, and the tour shows the way step by step.

      All tours and languages in one list: the list of tours. The tour starts by itself and waits for you to do each step. The playground changes three things in Joomla's Guided Tours plugin: the tour does not start again inside dialogs such as Menu Item Type, a tour of an earlier playground in the same tab does not continue halfway, and the editor's dialogs and Joomla's Preview come above the tour's overlay, so they can be clicked.

      Using the playground

      You see Joomla's administrator after a few seconds, already logged in as a Super User.

      The toolbar

      ButtonWhat it does
      Site / AdministratorShow the front end or the administrator of the site.
      NewStart a new, empty playground.
      Start overThrow this playground away and start again from the same link (and blueprint).
      Save…Keep this playground in your browser under a name. From then on, changes are saved as you work.
      My sitesOpen, rename or delete the sites you saved.
      MailThe mails the site sent. They are caught here, not delivered: try a password reset or a contact form.
      ExportDownload the whole site as a zip.
      Import…Start a playground from such a zip, e.g. one someone sent you.
      GitHub token…With the Patch Tester: the GitHub token this browser remembers for it (see Test a pull request).

      On the right:

      • Joomla switches the Joomla version: a new temporary playground starts with it. The -dev versions are nightly builds of Joomla's branches. The newest is the development branch: the next minor version, which most pull requests are for. The others (such as 6.2-dev and 5.4-dev) are the branches of the releases, with the fixes for their next patch release. The playground takes a new nightly build on days a branch has changed, and moves on after each release. A saved site keeps the version it was made with.
      • PHP switches the PHP version (8.3, 8.4 or 8.5): a saved site reopens with it, a temporary playground starts again from the same link.
      • The Super User's name and password. Hover over the database driver for timings.

      Logging in

      The playground logs you in to the administrator by itself. If you log out, or want to log in on the front end: the username is admin, and the password is different for every playground. The toolbar shows it ("Super User: admin / …"), and so does the login form. A saved site keeps its password. A session lasts 4 hours (Joomla's default is 15 minutes); change it under System > Global Configuration > System > Session Lifetime.

      Temporary or saved?

      • A new playground is temporary: reloading the page or closing the tab throws it away.
      • After Save…, the address bar shows ?site=<name>. That address reopens the site, also after a reload or a browser restart, and it is listed under My sites and on this page.
      • A saved site stays in this browser only (in its private storage for this website). Use Export to move a site to another browser or computer, or to keep a copy elsewhere.
      • A saved site can be open in one tab at a time.

      Good to know

      • Use a recent Chrome, Edge or other Chromium browser; Firefox and Safari are not tested yet.
      • Languages: System > Install Languages works. The playground has the accredited language packs on board, so installing one takes a few seconds. ?language=nl-NL starts a playground in that language.
      • The site reaches the internet through your browser, so only servers that allow requests from other websites (CORS) answer. Installing or updating extensions from URLs mostly does not work: download the zip and use System > Install > Extensions > Upload Package File. A link or blueprint can install extensions from hosts that allow it.
      • The Mail inbox keeps the mails until the page is reloaded.
      • Each tab is its own playground, with its own site and database.
      • Clearing your browser's site data for this address deletes the saved sites.

      Make your own link

      Parameters set up a new playground; combine them with &.

      • A site in Dutch ?language=nl-NL
      • PHP 8.5 ?php=8.5
      • Open the front end ?url=/index.php
      • Start logged out ?login=no
      • Install an extension ?extension=<zip URL>
      • Your own blueprint ?blueprint-url=<JSON URL>

      language?language=nl-NLInstall that language and make it the default of the site and the administrator

      Blueprints: a site set up by a JSON file

      A blueprint is a small JSON file with the steps to set up a site. Give its address with ?blueprint-url=, or put it in the address itself, after #. This one installs Joomla's blog sample data, renames the site and opens the front end:

      {
  "preferredVersions": { "joomla": "6.2", "php": "8.4" },
  "landingPage": "/index.php",
  "steps": [
    { "step": "importSampleData" },
    { "step": "setGlobalConfig", "values": { "sitename": "My demo" } }
  ]
}
      StepPropertiesWhat it does
      installExtensionurlInstall an extension package (zip)
      enableExtensionelement, type, folder, client, paramsEnable an extension and set its options, e.g. {"element": "debug", "type": "plugin", "folder": "system"}
      importSampleDatatype (default blog), group, queryInstall Joomla's sample data, or data of a plugin that works like it
      setGlobalConfigvaluesSet Global Configuration options (properties of configuration.php)
      setSiteLanguagelanguage, administratorMake a language the default (its pack is installed if needed)
      runSqlsqlRun SQL statements (MySQL syntax; #__ is the table prefix)
      runPHPcodeRun PHP code in the site's root folder
      writeFilepath, dataWrite a file into the site
      unzipurl, toUnpack a zip into the site
      loginLog in as the Super User (done by default)
      installLanguagelanguage, publishInstall a language and publish its content language
      addModulemodule, title, position, client, params, languagePublish a module on all pages
      addArticletitle, text, category, language, featuredAdd a published article
      addUserGrouptitle, parentAdd a user group
      disableExtensionelement, type, folder, clientDisable an extension
      indexSmartSearchBuild the Smart Search index, like its Index button

      Any step can have "background": true: it then runs after the playground is ready, while you use it, and the toolbar shows its progress.

      Downloads (extension, installExtension, unzip) need a host that allows it (CORS headers), such as GitHub Pages or raw.githubusercontent.com; release downloads on GitHub do not. URLs in a blueprint are relative to the blueprint. If a step fails, the playground still starts and the toolbar shows the error.

      Putting an exported site on a server

      An export (Export in the toolbar) is a complete Joomla site that runs on SQLite, with the playground's database driver and its database in data/joomla.sqlite. It runs on an ordinary PHP web server, without MySQL. That is fine for a demo or test site. Joomla itself does not support SQLite, so for a real site, move it to MySQL.

      How to put it on a server (PHP 8.3 or newer, with pdo_sqlite)
      1. Unpack the export in the web root.
      2. Edit configuration.php: $live_site = '';; set $tmp_path and $log_path to the full paths of tmp and administrator/logs on the server; and give $secret a new random string. The playground's is the same in every playground.
      3. Protect the database. data/joomla.sqlite holds the whole site, password hashes included. On Apache, data/.htaccess blocks it. On nginx, add a rule that denies /data/, or move the file outside the web root and set $db in configuration.php to its path. PHP must be able to write the file and the data folder.
      4. Set a new password for the Super User. The playground's password was public in its toolbar: php cli/joomla.php user:reset-password --username=admin

      Optionally, remove the playground's certificate from libraries/vendor/composer/ca-bundle/res/cacert.pem: the block between the two "Joomla Playground CA" lines. Its private key is gone, so it does no harm, and the next Joomla update replaces the file anyway.
